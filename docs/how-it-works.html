Who owns this process?

At the OS layer every action is just a process making a syscall. Praxis only gates processes that belong to an agent — your own apps are never prompted. Click a process to run a delete from it.

Attribution → principal → verdict

Click a process on the left
Every syscall carries a pid. Praxis walks the process tree: if the process descends from a known agent app, it's agent:* and gets policy; otherwise it's you and flows freely.

Why this matters

The same command rm x is allowed or gated purely by which branch of the tree it grew from. Your terminal's rm and Codex's rm are identical syscalls — attribution is what tells them apart. That's the OS-level version of the MCP principal, and it's why a real user is never spammed with prompts.

Hard parts (staff signal): pid reuse → pin identity at exec-time & track the tree; agent-created scripts run later → taint them; shared helper daemons → attribute per-request, not per-process.

The 6-line whiteboard

  1. Agents act; nobody guards the action boundary → Praxis returns allow/block/ask there.
  2. An unforgeable principal (local key/HMAC vs agent token) rides a normalized ActionEvent.
  3. Policy = principal × risk-tier matrix + deterministic→embedding classification + user config.
  4. Executor = fail-closed pipeline: kill-switch → policy → approval → dispatch; destructive → trash-first.
  5. Evidence = append-only SHA-256 hash chain (tamper-evident).
  6. Today MCP + on-device + offline. Next: OS-level (EndpointSecurity/eBPF) for guaranteed interception.
